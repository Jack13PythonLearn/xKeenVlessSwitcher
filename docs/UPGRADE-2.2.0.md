# Обновление до 2.2.0 и восстановление

Перед установкой на рабочий роутер сохраните ZIP из панели, каталог приложения и действующие конфигурации Xray. Обновление включает новый вход по ключу; установку согласуйте с владельцем роутера. Порт и маршруты автоматически не меняются.

## Вход

При первом запуске создаётся `data/admin-key` с правами 0600. На штатной установке прочитайте его через SSH Entware:

```sh
cat /opt/etc/xkeen-switcher/data/admin-key
```

Введите ключ в форме входа. Он не включается в экспорт настроек и не сохраняется в localStorage. Сессия действует 12 часов и сбрасывается при перезапуске панели. Для восстановления доступа используйте этот же файл. При утрате или компрометации ключа остановите панель, переименуйте `admin-key` в защищённую локальную копию и запустите панель: будет создан новый ключ, прежние сессии перестанут действовать. Не публикуйте ключ или ссылку подписки.

Для доступа по собственному DNS-имени укажите его в переменной `XKEEN_ALLOWED_HOSTS` при запуске. По умолчанию разрешены IP-адреса, localhost и имя устройства. API принимает сессионную cookie либо Bearer-ключ; запросы с чужим Origin отклоняются.

## Приватный GitHub

Для проверки и загрузки обновлений нужен токен с правом чтения содержимого именно этого репозитория. Сохраните его локально в `data/github-token`, установите права 0600. Токен не передаётся браузеру и не входит в резервную копию. При отсутствии доступа панель показывает ошибку проверки обновлений.

Источник — ветка main настроенного репозитория. Обновление фиксирует SHA коммита, проверяет Git SHA каждого файла и синтаксис JavaScript. Загружаются только код, ресурсы public и файлы lib; пользовательская база не заменяется. Если источник изменился после проверки, загрузку нужно повторить.

Встроенная установка работает только при запуске панели штатной службой Entware с действующим PID-файлом. Независимый процесс сохраняет копию кода, устанавливает файлы, перезапускает панель и проверяет её версию. При неудачном запуске восстанавливается предыдущий код. Это защищает от проверенных ошибок записи и запуска; внезапное отключение питания посреди установки требует ручного восстановления.

Состояние: `data/update-status.json`. Сохранённый каталог обновления указан в поле `stage`. Для ручного отката остановите панель и выполните следующую команду, подставив точный путь из этого файла:

```sh
node /ТОЧНЫЙ_ПУТЬ_К_STAGE/worker/update-worker.js /ТОЧНЫЙ_ПУТЬ_К_STAGE/job.json --rollback
```

Не удаляйте stage до проверки новой версии. После успешной установки можно удалить старые stage-каталоги вручную. Они содержат резервный код, а не экспорт подписки.

## Повреждённая база

Некорректный `profiles.json` не заменяется пустой базой. Перед каждой записью сохраняется предыдущая корректная версия в `profiles.json.last-good`. Это предыдущая запись, а не ежедневный архив.

Для восстановления остановите службу, сохраните повреждённый файл отдельно, проверьте JSON в `.last-good`, скопируйте его в `profiles.json` и запустите службу. При сомнении используйте заранее сохранённую полноценную копию каталога. Сначала сохраните повреждённый файл: он может содержать более свежие настройки.

## Проверка после установки

1. Вход, перезагрузка страницы, сохранение настроек без изменения порта.
2. Число подключений, подписки, правила и текущий сервер совпадают с состоянием до установки.
3. Ручное переключение и фактическая маршрутизация подтверждены на клиентском устройстве.
4. Пустой пул нельзя включить; отключение автоматики отменяет уже начатую проверку.
5. Проверка приватного GitHub с настоящим токеном.

Смена порта, отключение серверов и отказ рабочего Xray проверяются отдельно после согласования. Локальные тесты не заменяют эти проверки на Entware.
